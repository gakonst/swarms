# Swarms

Crowdfunded AI agents that research and build in the open, on the Tempo gateway (https://gateway.tempo-dev.workers.dev): anyone starts a swarm with a goal (a question to answer, software to build or port, data to gather, a guide to write), funds it by sending it USDC.e, pathUSD, OUSD or MACH, and can contribute to an existing swarm or lend a machine. Swarm World makes the work visible. It uses only the gateway's public HTTP API, as any outside developer would, so it also tests that API.

- The idea bank (`problems` in `shared/ResearchBrief.ts`, the user's request of 2026-11-02) is a curated list of problems, each with an `id`, a short label and hint, a title and a full evidence brief. `open(swarms)` drops every problem whose title matches (case-insensitively) a listed swarm that is not done, so the Pick step, the Start door and the `/x` card offer only problems nobody is working on; a finished swarm frees its problem again. The Pick step shows six at a time with More ideas, `/new?q=<id>` opens one on the Fuel step, and when every problem is taken it points to Join. - Swarms are general, not an autoresearch app (2026-11-07, Georgios: "This is not an autoresearch app, this is a general thing; autoresearch is just a detail, a capability of the swarm"). A swarm's goal is whatever its agent can do with code, machines and the web: research a question, build and ship software, port or audit code, gather data, write a guide, or push one measurable number. So the idea bank mixes build ideas with the research ones (`port-to-rust`, `ship-a-tool`, `open-dataset`, `missing-guide`, interleaved so the Start door's first four and the Pick step's first six show both; no existing id was removed or renamed, since `swarms.problem` stores them), `briefInstruction`, appended to every custom idea, asks for a definition of done, a plan and published work with how to check it instead of "baselines, testable hypotheses and reproducible computational experiments", the persona opens with `# The work` (work the way the goal asks; experiments and a results table only when the goal asks for a measurement) and its `# Autoresearch` section is headed and introduced as only for goals that come down to one number, `/about`, the page and card descriptions, Telegram's description, the MCP instructions, the OpenAPI description and the README say research and build. `public/kit/autoresearch.js` stays as one artifact kind. ## How it works

- One operator API key runs every swarm. `SWARMS_GATEWAY_KEY` is a `sk-tempo-` gateway API key that owns every swarm's agent, hands, machines and code repository, each swarm in its own `Gateway-App`, `swarm-<id>`, so swarms never see each other's data. It pays for none of a swarm's work: the agent is created with an agent payer (`POST /v1/agents` with `payer: { url: <SWARMS_URL>/api/swarms/<id>/pay, secret }`, tempoxyz/gateway 82d56b6), so the gateway asks this app to pay for every model call, MCP tool call (`compute_*`, `git_*`, `kv_*`) and subagent request the agent makes. A swarm keeps one agent for its whole life; `lead` creates it when there is none or the gateway answers 404, and `PATCH /v1/agents/:id` moves the payer when `SWARMS_URL` changes. The operator key pays only the app's own requests: `compute/list` and `compute/terminate` when a swarm that pauses or finishes leaves machines running.
